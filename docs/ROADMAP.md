# Sales Coach 开发路线

| 阶段 | 交付与验收门槛 |
| --- | --- |
| 2.2 百炼真实评分 | 最小请求先通过，随后 A/B/C 三组报告通过结构、原话、权限、存取和幂等检查。 |
| 2.3 对话与评分质量 | 版本化评测集、多场景和两场真实十轮对话。验证难度、顾虑变化、记忆与事实一致性。 |
| 3 语音 | 验证中文识别、语音回复、打断和重连。付费服务须先确认。语音可以独立于文字公开测试发布。 |
| 4 账号与数据 | 注册、登录、身份验证、多设备、导出和删除。验证数据归属、匿名迁移和数据库升级。 |
| 5 产品体验 | 桌面和移动端新手流程、状态提示、可访问性与按评分版本区分的成长记录。 |
| 6 成本与额度 | 用户和系统额度、并发保障、用量统计、限流与防重复扣减。支付可独立发布。 |
| 7 安全与可靠性 | 安全审查、故障矩阵、性能基线、备份恢复、隐私与合规人工审查。 |
| 8 预发布与生产 | 基础设施、CI、HTTPS、监控、预发布真实流程、恢复演练和发布授权。 |

V1 公开测试包含账号、文字训练、真实评分、成长记录、免费额度和基础运维。语音与商业化延后独立验收。代码、本地验证、预发布与生产分别报告状态。

当前已到达本地文字候选验证。发布前须核验生产邮件、Linux 容器和 HTTPS、异机备份、告警、正式环境安全与隐私，并取得发布授权。[执行结果](TEST_REPORT.md) · [外部阻塞](BLOCKERS.md)

## 免费文字版公开发布门槛

本机最终验收已经通过。下一步在独立 Linux 预发布环境运行容器验收，配置正式邮件发送并核验公共证书，实测异机恢复与 GitHub 审批，再申请公开发布授权。语音和支付使用独立候选与验收。详见 [最终候选报告](RELEASE_REPORT.md)。

## 当前优先级

迭代按真实用户影响排序。先稳定文字训练、AI 客户与可解释评分，完善移动端、异常提示、注册登录、用户数据管理和隐私与协议审阅准备。同步验证 Token 与费用口径、额度限流、在线备份和恢复。通过独立 Linux 生产栈验收邮件、HTTPS、监控、日志和安全后，再进入文字版正式上线与第一轮真实用户测试。

## Phase A — Product Hunt 发布与宣传

暂缓至文字版正式上线并完成第一轮真实用户测试。后续完成产品定位与差异化、Product Hunt 页面、Logo、产品截图、演示视频、发布文案、Maker Comment、发布日计划与用户反馈收集。

## Phase B — 社交传播与分享

与 Phase A 独立，启动门槛相同。后续支持由用户主动发起的训练报告和成长成果分享、可公开访问的分享页面、链接权限与有效期、隐私保护、社交媒体预览、OG 图片和分享渠道适配。

分享默认私有。销售对话、客户画像和私人训练记录只能在用户明确授权后公开。分享设计需验证字段最小化、链接过期、撤销和跨用户隔离。
